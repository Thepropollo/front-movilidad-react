# Hallazgos de auditoría del frontend — línea base y estado de correcciones

Fecha: 2026-09-29  
Rama: audit/frontend  
Alcance: snapshot actual del frontend, incluyendo los cambios locales que ya existían al iniciar la auditoría. Esos cambios se conservan y no se consideran commits de esta auditoría.

Las cuatro matrices solicitadas al inicio no existen en el repositorio. Se contrastaron las rutas con el código de backend disponible. No se pudo ejecutar el backend ni recorrer pantallas autenticadas; todo lo que depende de ejecución queda indicado como No verificado.

La tabla de abajo registra la línea base anterior a los commits de corrección. El campo Estado se actualiza con el resultado al cierre; para el estado final y las limitaciones vigentes, véase `frontend-reporte-final.md`.

## Decisiones que requiere el responsable del sistema

1. Liquidación docente y compensación del conductor: ¿son dos procesos? La API actual modela DriverCompensation y su pantalla de aprobación es de Secretaría; el frontend también presenta una liquidación desde docente que no coincide con ese permiso. No se debe habilitar una subida simulada como comprobante.
2. Auditoría administrativa: ¿entran en el alcance las rutas CRUD/logs del backend? El catálogo canónico no define admin; “Secretaría / Administrativo” es la etiqueta frontend para secretaria y jefe_transporte es un alias backend.
3. Cookies HttpOnly: no se encontró contrato de autenticación por cookie; el bearer token se persiste en localStorage hasta que backend soporte otra modalidad.
