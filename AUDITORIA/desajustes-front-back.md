## Pantallas/endpoints que requieren definición

- Pantalla docente de liquidación frente a compensación de conductor: pedir decisión al responsable. No se debe enviar el flujo docente al endpoint reservado a Secretaría.
- Lista general de consumos para Secretaría: el backend tiene orden individual y lista propia para el conductor; no se encontró endpoint de historial general.
- /logs-sistema y /admin/*: confirmar si deben tener UI y cuál rol organizacional administra esas operaciones. No hay rol canónico independiente de administrador.

## Alcance y estado de verificación

- Autorización externa: el código implementa Secretaría y después Vicerrectorado; no son rutas alternativas. Evidencia: `AutorizarSecretariaController.php` cambia a `pendiente_rectorado` y `AprobarRectoradoController` procesa ese estado.
- La reasignación tras rechazo tiene pantalla, `PATCH /hojas-ruta/{id}/reasignar` y middleware Secretaría. La consulta de combustible del conductor tiene pantalla y `GET /mis-ordenes-combustible`; el historial agregado de consumos para Secretaría no tiene pantalla/endpoint identificados.
- No se verificaron contratos por HTTP, permisos con varias cuentas, datos persistidos ni traspasos entre actores: el backend no estaba activo y no había credenciales de prueba.
- El inventario encuentra tarjetas con rutas UI no declaradas o rutas de otro rol en varias pantallas. Se listan en `inventario-acciones.md`; permanecen como pendiente cuando su corrección exigiría decidir el destino o el rol adecuado.
